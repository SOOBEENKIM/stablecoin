# 성능 개봉 전 검증기 수정 기록

최초 `hs_verify.py`는 1h/original/R/2026-03/linear의 후보 대조에서 중단됐다. 예측 봉인 후이며 `SCORES_OPENED.json`은 생성되지 않은 시점이었다. 실패 지점은 `assert note.candidate == chosen`이다. 원본 검증기는 보존한다.

원인은 NumPy mean과 pandas groupby mean의 부동소수점 합산 차이를 동점 처리에 반영하지 않은 **검증기 결함**이다. 회귀/예측 모형의 버그로 판단하지 않는다.

- 원 실행의 NumPy 내부 손실: 후보 0(level,alpha0)과 후보 3(change,alpha0) 모두 `1.7133586660192421`.
- 미리 고정한 규칙은 동일 점수이면 작은 후보 ID를 선택하므로 저장된 후보 0이 규칙에 맞는다.
- 독립 pandas 합산: 후보 0은 `1.7133586660192424`, 후보 3은 `1.7133586660192421`로 약 2.22e-16bp 차이가 생겨 후보 3을 선택했다.
- 두 후보의 해당 내부 구간 보정 예측 최대 차이는 `2.842170943040401e-14`bp.

`hs_verify_v2.py`는 독립 손실 계산과 groupby 평균을 유지하면서 (1) 둘의 합산 차이가 16 machine eps × max(1,score) 이내인지, (2) 저장된 선택이 원래 NumPy 점수/작은 ID 규칙과 **정확하게 같은지**, (3) 독립 점수에서도 기계 정밀도 오차 이내의 최소인지 각각 검증한다. 실제 점수차를 허용해 더 나쁜 모형을 통과시키는 규칙이 아니며, 저장 후보를 3으로 바꾸면 테스트가 실패한다. 후보 0 손실에 0.001bp를 추가한 경우도 실패한다. 모든 동점 차이를 별도 JSON으로 기록한다.
