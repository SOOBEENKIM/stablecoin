# 고정된 교차 설계의 실행 명세

2026-09-25. 사용자가 설계대로 구현·검증한 뒤 전체 비교를 실행하도록 지시했다. [기존 설계](../residual_factorial_design/PROTOCOL_KO.md)와 `DESIGN_LOCK.json`은 수정하지 않는다. 그 폴더의 '미실행' 표시는 설계를 작성한 시점의 기록이다. 이번 폴더가 실제 실행을 담당한다.

## 변경하지 않는 통계적 설계

R/B/F 3입력 × 선형/QRF/분위수 부스팅/문턱형 4계열, 입력당60개 후보, 주 조건4seed, CAP/PCA/strict 첫seed를 그대로 사용한다. 준비 기간8월, 내부 선택9월부터, 평가12월~3월이다. 후보별 자기 원예측 오차로 보정하고 직전3개월의 보정 후 손실로 선택한다. 주 비교6개와 Holm 가족, 1/5/10일 달력 블록, 1,999회, 원예측 진단, 월별·seed별 비교를 유지한다.

각 계열별 결과와 ML 선택 결과는 별도로 내며 모든 칸에 같은 평가 표본과 목표를 쓴다. 기존10.65%를 전체 입력 칸에 붙이지 않는다. F에서 선택한 같은 후보 ID를 R/B/F에 적용하되 각 입력에서 재학습한 계수·트리와 각자의 보정 오차를 쓰는 `matched_full_spec`도 저장한다.

구현상 추가로 명시한 보조 비교는 QRF/부스팅 각각의 R/B/F 선형 대비6개, B의 ML 선택 대 선형1개, 같은 설정의 시장/포지셔닝/전체 정보 비교3개다. 이는 주 비교 가족을 늘리거나 바꾸는 것이 아니다. 보조 표의 p값을 새 확증적 발견으로 선택하지 않는다.

## 적합과 저장

- 4조건 × 8개월 × 3입력 × 4계열 =384개 작업 단위다. 작업 내부에서 고정 후보·seed를 계산한다. CPU 프로세스16개를 기본으로 사용하고 각 프로세스의 BLAS/OMP/MKL 스레드를1개로 제한한다.
- 요청된 적합 조합은10,080개다. 난수를 쓰지 않는 선형/문턱형의 같은 적합은 주 조건의 추가seed에서 캐시한다. 합성자료에서 seed에 따른 예측의 정확한 일치를 검사했다. 따라서 실제 적합 예정 수는7,488회, 캐시 재사용은2,592회다. QRF/부스팅의 난수seed는 각각 적합한다.
- `results/candidates/`의48개 파일에 모든 후보의 원예측·보정·정답·시점·보정 이력을 저장한다. 예상1,260개 후보 계열,2,735,460행이다. 선발되지 않은 후보도 삭제하지 않는다.
- 선택된15개 칸과 같은 설정3개 칸을 `predictions.csv.gz`에 저장한다. 주1,088개 시점×4seed, CAP/PCA 각1,088개×1seed, strict467개×1seed이므로 총125,910행을 예상한다. 시간 표본 수를 seed만큼 늘렸다고 해석하지 않는다.
- 내부 점수2,880개, 선택 기록288개, 적합/캐시 메타데이터10,080개를 저장한다. 월별 학습 경계·실제 입력·잔차 분해 계수·경고를 포함한다.
- 실행 중간 캐시는 저장소의 ignored `.runs/residual_factorial_execution/`에 둔다. 중단 시 `--resume`은 같은 실행 잠금 및 체크포인트 해시가 맞고 아직 예측 봉인 전인 경우에만 가능하다. 유리한 점수를 위한 재시작은 허용하지 않는다. 봉인된 예측과 과거 결과는 덮어쓰지 않는다.

## 실행 전 검사

기존 설계의8개 합성 검증과 새 실행기의10개 검증을 수행한다. 추가 검증은 제한 입력 모형의 학습/예측에서 제외 변수와 미래 정답을 교란해도 결과가 같은지, 선형/문턱형의 seed 캐시가 정확한지, QRF를 트리별 잎 이웃에서 독립적으로 계산한 분위수와 맞추는지, 실제 시계의 누락 시간을 건너뛰지 않는지, 미래 패널 값이 과거 분해 추정을 바꾸지 않는지 등을 확인한다.

합성 후보 파일부터 내부 선택·월별 예측 연결·같은 설정의 정보 비교까지 실행해 후보별 보정 이력을 잘못 섞지 않는지 검사한다. 짝지은 블록 계산은 관측행 가중치 방식과 실제 뽑은 날짜의 행을 합치는 방식으로 대조한다. 관측치가 없는 재표집을 조용히 버리지 않고 중단하는 동작과 잠금 파일 덮어쓰기 거부도 검사한다.

개발 중 매우 희박한 합성 달력에서 빈 재표집에 대한 중단이 발생해 이를 별도 검증으로 유지했다. 과거 실험의 `run.py`와 혼동되는 테스트 import도 발견해 새 실행기를 `factorial_run.py`로 명명했다. 이 수정들은 실제 성능 실험 전에 이루어졌고 데이터·모델·비교 규칙은 변경하지 않았다.

## 실행·봉인·검증·개봉

1. `PRE_RUN_TESTS.txt`와 실행 코드·검증/평가 코드·이 명세·기존 설계 및 의존 소스·원자료·패키지 버전을 `LOCK.json`으로 고정한다. commit/push 후에만 실제 후보 예측을 시작한다.
2. 모든 후보를 적합하고 각자의 과거 오차로 보정한다. 내부 선택의 입력에는 직전3개월과 그때 알려진 정답만 전달한다. 후보 누락·비유한 예측·해결되지 않은 적합 경고를 조용히 탈락 처리하지 않는다.
3. 모든 후보와 선택 예측·메타데이터 해시를 `PREDICTIONS_SEALED.json`에 봉인한다. 외부 성능 요약을 먼저 보고 남은 후보나 비교를 중단하지 않는다.
4. `verify.py`는 별도 순서통계량 구현으로1,260개 후보 보정을 재계산하고, 독립 손실 계산으로2,880개 내부 점수와288개 선택을 대조한다. 같은 시점에 도착한 정답을 제외하고 미래 정답 교란의 영향을 검사한다. 선택 예측은 해당 입력/후보/seed의 원래 계열과 행별 대조한다.
5. 원자료 파생상품 지표의5분 지연을 독립적인 시각 검색으로 재확인한다. 환율·포지셔닝·거시 관측 경과시간 조건, 기존 평가 정답·시점과 일치, 모든 적합의 월 경계·입력 목록을 확인한다. 이는 공급자의 원 시각 표기가 사실인지까지 검증한 것은 아니다.
6. 1월의 모든 정보×선택 계열×seed와 같은 설정 비교에 필요한 고유 모형을 실제 재적합한다. R/B는 제외 입력을 학습·예측에서 교란한 재적합도 비교한다. 주6개 손실 벡터의 재표집은 일별 합산의 독립 구현으로 대조하되 이 단계에는 외부 성능 결과를 출력하지 않는다.
7. 검증 통과를 `VERIFICATION.json`에 기록한 뒤 `SCORES_OPENED.json`을 만들고 모든 고정 비교를 평가한다. `--reproduce`는 봉인된 같은 예측의 평가 재현에만 사용한다. 설계·후보·대상 기간을 바꾸는 옵션이 아니다.

## 실행 명령

저장소 루트에서 다음 환경변수를 각 명령에 적용한다.

```bash
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
export MPLCONFIGDIR=/tmp/stablecoin-factorial-mpl
python3 experiments/residual_factorial_execution/execution_guard.py verify
python3 experiments/residual_factorial_execution/factorial_run.py --workers 16
python3 experiments/residual_factorial_execution/verify.py --workers 16
python3 experiments/residual_factorial_execution/evaluate.py
```

재현된 수치가 좋은지와 별개로 이미 사용했던 기간의 재평가라는 한계는 남는다. 같은 예측의 블록 신뢰구간은 과거 인간의 반복 탐색이나 새 시장 국면의 불확실성을 모두 포함하지 않는다. 이번 실행 범위는 고정된 교차 비교이며 후속 위험 경보·1/6/12시간 가격 경로 실험은 포함하지 않는다.
