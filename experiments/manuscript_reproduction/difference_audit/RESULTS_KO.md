# PDF와 GitHub 재실행 수치가 다른 원인

2026-09-25. 대상은 첨부 최종 원고와 `runs/default_B300` 재현본의 표 1–6이다. 기본 재현본은 185개 숫자 중 173개가 일치하고 12개가 다르다. **12개 중 10개는 통제한 재실행으로 차이의 원인을 설명했다. 나머지 2개는 계산값과 원고의 불일치를 확인했으나, 원고 값의 실제 작성 경위는 확인하지 못했다.**

이번 차이는 행 시차를 실제 시간 시차로 수정해서 발생한 것이 아니다. 원본 입력, 잔차, 표본과 행 이동은 그대로다. GitHub의 기존 기본 재현 결과도 덮어쓰지 않았다.

## 1. 표 5의 계수 1개: 회귀 계산 반복 횟수 차이

현재 `kp_robustness.py`는 분위수 회귀의 IRLS 근사 계산을 최대 70회 반복한다. 같은 입력·공통 요인·표본을 유지하고 최대 반복만 60회로 바꾸면, 원고의 근거인 과거 CSV에 저장된 **EQ·CAP·PCA의 15개 계수 전체**가 일치한다.

| CAP, q=0.10 | 계수 |
|---|---:|
| 현재 코드, 반복 70회 | -8.922 (CSV 값) |
| 반복 60회 | -8.815 (CSV 값) |
| 과거 저장 CSV | -8.815 |
| PDF 표시값 | -8.82 |

차이는 시총 가중 방식이나 데이터 변경이 아니라 **같은 근사 회귀를 어디서 중단했는가**에서 생긴다. 60회가 원고를 재현한다는 사실이 60회의 추정이 더 정확하다는 뜻은 아니다. 수치해법의 수렴 검증은 이후 수정 단계에서 다룰 문제다.

증거: [반복 40·60·70·80회 비교](coefficient_iterations.csv). 15개 과거 계수 중 일치 개수는 각각 3·15·6·6개다. 이 범위는 다른 원본 코드들에 쓰인 반복 횟수를 바탕으로 확인했으며, 모든 결과를 공개한다.

## 2. 표 5의 p값 3개: 부트스트랩 150회와 300회의 차이

회귀 점추정 반복 60회, 부트스트랩 내부 회귀 반복 35회, seed=42를 고정한 상태에서, 부트스트랩을 **150회** 실행하면 당시의 두 저장 CSV가 모두 재현된다. 현재 재현본은 코드 기본값인 **300회**를 사용했다.

| 표 5 항목 | 현재 기본 재현 B=300 | 추적한 B=150 설정 | PDF |
|---|---:|---:|---:|
| EQ q=0.50 p값 | 0.013 | 0.000 | 0.00 |
| CAP q=0.10 p값 | 0.120 | 0.107 | 0.11 |
| CAP M2 레버리지 p값 | 0.007 | 0.000 | 0.00 |

확인은 PDF의 몇 개 숫자만 맞추는 수준에 그치지 않는다. `robustness_kp_main_quantile.csv`의 60개 셀과 `robustness_kp_mediation.csv`의 63개 셀이 모두 일치한다. 여기에는 이름·분위수·판정 등 비수치 셀도 포함된다. 후자의 마지막 열 이름 `result`와 과거의 `mediates`는 비교할 때만 대응시켰다. 파일 바이트가 같다는 주장은 아니다.

통제 순서는 다음과 같다.

| 점추정 반복 / 부트스트랩 내부 반복 / B | 과거 main CSV | 과거 channel CSV |
|---|---:|---:|
| 60 / 35 / 300 | 53/60 일치 | 56/63 일치 |
| **60 / 35 / 150** | **60/60 일치** | **63/63 일치** |
| 60 / 30 / 150 | 58/60 일치 | 58/63 일치 |

이 설정은 과거 결과 전체를 생성하는 수치적 경로로 확인됐다. 당시 실행 명령 자체를 담은 로그가 발견된 것은 아니므로, 역사적으로 유일한 실행 경로임을 주장하지 않는다. 이번 결과를 더 유의하게 만드는 연구 모형 선택으로 사용하지 않는다.

## 3. 표 6의 p값 6개: 부트스트랩 200회와 300회의 차이

원본 `experiment2_subsample_stability.py`의 **B만 300에서 200으로 변경**하면 PDF 표 6의 20개 숫자가 전부 일치한다. 저장 CSV의 전체 45개 셀도 일치한다. 계수·관측수·표본 분할·행 시차·데이터는 바꾸지 않았다.

| 표 6 항목 | B=300 | B=200 = PDF |
|---|---:|---:|
| 전체 표본, 레버리지 p | 0.000 | 0.010 |
| 최대 5일 제거, 하방위험 p | 0.027 | 0.050 |
| 전반부, 하방위험 p | 0.987 | 1.000 |
| 전반부, 레버리지 p | 0.513 | 0.450 |
| 후반부, 하방위험 p | 0.273 | 0.320 |
| 후반부, 레버리지 p | 0.513 | 0.490 |

원본 코드의 p값은 부트스트랩 계수의 부호 빈도로 계산한다. B가 달라지면 표본 추출 횟수가 달라지고, 하나의 전역 난수 생성기를 여러 모형에서 연속 사용하므로 다음 모형에 전달되는 난수 상태도 달라진다. 따라서 seed=42가 같아도 B나 호출 순서가 다르면 p값은 달라진다. 같은 코드·환경·B·호출 순서에서는 재현되므로 단순히 “실행할 때마다 랜덤하게 달라진다”는 설명은 부정확하다.

증거: [B=200 출력](../runs/archive_supplement_B200/paper_outputs/exp2_subsample_stability.csv), [기존 저장 CSV와의 전체 대조](../comparison/archived_csv_comparison.csv).

## 4. 표 4의 p값 1개: 원고의 0.05는 정확한 출처 미확인

원고의 `M2, BTC 변동성`은 β=-0.275, p=0.05다. 계수는 재현되지만 p값은 전체 원본 실행에서 0.027이다. 이는 두 자리로 표시하면 **0.03**이며 0.05로 반올림되지 않는다.

추가로 확인한 사실:

- 워크스테이션 `stablecoin` 및 `stablecoin_v3`의 과거 저장 결과에도 이 p값은 **0.027**이다. 새 GitHub 환경에서만 생긴 차이가 아니다. [원본 출력 사본과 해시](evidence/source_manifest.json)를 보존했다.
- `stablecoin_v4/manuscript_경영과학_김수빈_v4.docx`에는 이미 **0.05**가 적혀 있고, 최종 원고에도 같은 값이 있다. 따라서 6월 26일 최종 원고 편집에서 새로 생겼다고 단정할 수 없다.
- 같은 데이터·B=300·seed=42에서 M0/M1/M2 표 함수만 단독 실행하면 **0.047 → 표시값 0.05**가 나온다. 그러나 이 실행의 다른 p값은 원고와 다르다. M1 하방위험 p는 0.313(원고 0.33), M2 하방위험 p는 0.247(원고 0.18), 레버리지 p는 0.000(원고 0.01)이다.
- 부트스트랩 내부 회귀 반복을 30·35회로 바꾸는 점검으로도 표 4 전체를 일치시키지 못했다.

즉 **실행 순서에 따른 난수 상태 차이로 0.05가 나오는 것은 실증적으로 확인**했다. 하지만 원고가 그 단독 실행값을 섞어 옮겼는지, 다른 실행을 참조했는지, 단순 전사 오류인지 판별할 당시 로그나 편집 이력이 없다. 오탈자라고도, 실행 순서 때문이라고도 확정하지 않는다.

## 5. 표 1의 왜도 1개: 원고의 4.90은 계산·작성 경위 미확인

같은 715개 관측치에서 `pandas.Series.skew()`는 **4.894514736426965**, SciPy의 편향 보정 왜도는 **4.894514736426964**다. 두 계산이 일치하며 두 자리 반올림은 **4.89**다. 편향을 보정하지 않은 SciPy 값도 4.8842405로, 원고의 4.90을 설명하지 못한다.

따라서 통상적인 반올림이나 이 두 구현의 차이로는 원고의 4.90이 나오지 않는다. 다른 중간 정밀도·원자료 버전·표 작성 과정이 있었는지 확인할 기록은 없다. **숫자가 잘못 옮겨졌을 가능성은 있지만, 원인을 전사 오류로 확정하지 않는다.** 표 1의 나머지 119개 숫자는 일치한다.

## 판정과 남은 범위

| 불일치 12개 | 설명 상태 |
|---|---|
| 표 5 계수 1개 | 회귀 점추정 반복 70회와 60회의 차이로 재현 확인 |
| 표 5 p값 3개 | B=300과 B=150의 차이로 재현 확인 |
| 표 6 p값 6개 | B=300과 B=200의 차이로 재현 확인 |
| 표 4 p값 1개 | 실행 문맥에 따라 원고값이 나오지만 실제 출처는 미확인 |
| 표 1 왜도 1개 | 보존 데이터·표준 왜도 계산과 불일치. 작성 경위 미확인 |

PDF 표 3은 main의 B=300 결과, 표 5는 위의 60/35/B=150 설정, 표 6은 B=200 설정과 일치한다. **기본값 B=300으로 모든 파일을 재실행한 묶음은 원고에 사용된 결과 묶음과 같지 않았다.** 앞서 원고 재현본을 만들면서 표별 설정까지 먼저 복원하지 않은 점 때문에 일부 차이를 설명하지 못했다.

표별 추적 설정을 적용해 비교하면 185개 중 183개가 표시 자릿수에서 일치한다. 이는 여러 표의 생성 경로를 분리한 대조 결과이며, 한 번의 동일 설정으로 원고 전체를 완벽히 재현했다는 뜻이 아니다. 원고 수치에 맞춘다고 p=0.05나 왜도=4.90을 출력에 직접 넣지 않았다.

행 시차/실제 시간 문제와 그림의 신뢰구간 생성 코드 부재는 별개의 문제로 남아 있다. 이번 작업은 숫자 차이의 원인 추적이며, 이론·인과적 해석의 타당성이나 수정 후 결과를 입증한 작업이 아니다.
